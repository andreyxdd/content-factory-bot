# Internationalization — v1

## Scope

| Surface | Languages | Source |
|---------|-----------|--------|
| Bot replies, buttons, errors | `en`, `ru` | `src/content_factory_bot/locale/{en,ru}.json` |
| Generated content (drafts, research brief) | Creator **primary language** | Prompt instruction + profile field |

## Detection (before / during first `/start`)

| Telegram `language_code` | Bot UI locale |
|------------------------|---------------|
| `ru`, `rus`, `ru-*` | `ru` |
| anything else / missing | `en` |

`LocaleMiddleware` sets `data["ui_lang"]` on every update from `message.from_user.language_code`.

On first allowlisted `/start`, `ensure_creator()` seeds `creators.primary_language` from the same rule. Onboarding question `primary_language` **confirms or overrides** that seed.

## Persistence

`creators.primary_language` — `en` or `ru`; seeded from Telegram on first start; confirmed in onboarding Q1; change via `/settings` or `/profile`.

## Rules

- **Bot UI** follows `ui_lang` (Telegram until profile exists; then stored `primary_language` in Phase 1 handlers).
- **Generated content** follows `primary_language` from profile.
- LLM: "Respond in {primary_language} unless user input is explicitly another language."

## Implementation phases

1. Phase 1: onboarding language picker + store field
2. Phase 1: `t(key, lang)` helper for static strings
3. Phase 2+: generate all command help from locale files
