## Log

### Q1 — Allowlist governance

**Question:** How does a Creator get on the allowlist, and who maintains it?

**Recommendation:** Curated static list in DB seeded from env `ALLOWLIST_TELEGRAM_IDS` for MVP; operator adds via SQL or future `/admin_allowlist`. No automatic "international" detection—manual invite-only.

**Alternatives:**

- A) Env-only list (simplest deploy)
- B) DB table + admin Telegram command (scalable)
- C) Invite codes (`/start invite_<token>`) tied to one-time redemption

**Answer:** **B** — DB table (`allowlist_entries`), seeded from `ALLOWLIST_TELEGRAM_IDS` at startup; live changes via SQL / future `/admin_allowlist`.

**Status:** ✅ resolved

### Q2 — MVP provider scope

**Question:** Which providers must work in the first shippable version?

**Recommendation:** **Telegram channel/group only** for MVP; Instagram and LinkedIn behind feature flags with `/providers` showing "coming soon". IG/LI app review routinely blocks a true v1 deadline.

**Alternatives:**

- A) Telegram publish only (recommended MVP)
- B) Telegram + Instagram
- C) All three (Telegram + Instagram + LinkedIn) in v1

**Answer:** **C** — all three providers required in v1 (user override of Telegram-only MVP recommendation).

**Status:** ✅ resolved

### Q3 — OAuth / provider connection UX

**Question:** How do Creators connect Instagram and LinkedIn given Meta/LinkedIn require a browser OAuth redirect (not completable inside a Telegram message)?

**Recommendation:** **B** — FastAPI sidecar serves OAuth start URLs; bot sends inline button “Connect Instagram” → opens browser → callback stores tokens. Telegram channel connection stays in-bot (forward channel post or `/providers` picks chat). Reject manual token paste (security + refresh hell).

**Alternatives:**

- A) Fully external admin panel only (creator never connects in bot)
- B) Bot deep-link / button → hosted OAuth web flow → callback (recommended)
- C) Manual token paste in chat (dev-only, not production)

**Answer:** **B** — bot inline URL → FastAPI OAuth start/callback. Operator has HTTPS domain; configure `PUBLIC_BASE_URL` + provider redirect URIs per `.planning/OAUTH-SETUP.md`.

**Status:** ✅ resolved

### Q4 — Refinement mode (single-option edit)

**Question:** When the Creator selects one draft option and asks to edit only that option, what does the next menu show?

**Recommendation:** **A** — **1 edited version of the selected option + 2 fresh alternatives** (4th button still custom reply). Keeps comparison without three near-duplicates.

**Alternatives:**

- A) 1 edited + 2 new options (recommended)
- B) 3 revisions of the same option only
- C) 1 edited only (no new alternatives until they ask)

**Answer:** **A** (user: "ok" — accepted recommendation).

**Status:** ✅ resolved

### Q5 — Session concurrency

**Question:** How many **content sessions** may be open (not `closed`) per Creator at once?

**Recommendation:** **A** — **one active session** per Creator. `/new` while another is open prompts: resume current, close and start new, or cancel.

**Alternatives:**

- A) One active session (recommended)
- B) Unlimited parallel sessions
- C) Cap at N (e.g. 3) with list picker

**Answer:** **A** (user: "agree").

**Status:** ✅ resolved

### Q6 — AI architecture

**Question:** How should research / writing / visual work map to LLM calls for draft rounds?

**Recommendation:** **B** — **Single orchestrator prompt** per draft round (personality profile + inputs + round history → 3 options JSON). Simpler FSM, one latency bill. Research-agent parity = optional pre-step or `/research` later, not separate agents in v1.

**Alternatives:**

- A) One monolithic prompt only (same as B but no structured sub-steps inside)
- B) Single orchestrator with internal chain-of-thought steps in one job (recommended)
- C) Three staged agent calls per round (research → write → format), OpenClaw-style

**Answer:** **B** (user: "agree"). **Transport:** direct API via OpenRouter (or any OpenAI-compatible gateway); Hermes = model choice only; Claude Code / agent harness = dev-only, not runtime. Detail: `.planning/AI-STACK.md`, ADR-0006.

**Status:** ✅ resolved
